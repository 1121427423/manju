# 10 · 动作镜的姿势链编排

> 目标：把 8 个动作镜头从"一张静帧"扩展成**连续姿势链**，用形态插值串成真正的连续动作。

## 实际落地：每镜 3 格，而不是 4 格

原计划每镜 4 格（`_p1`…`_p4`）。实做后调整为 **2–4 格**，理由是数据说话：

| 镜 | 格数 | 链 |
|---|---|---|
| 10 冲刺 | 3 | p1 蓄力 → p2 蹬地 → p3 光尾前送 |
| 11 剑伞相撞 | 4 | p1 将触 → p2 接触 → p3 外扩 → p4 余波 |
| 12 罗盘成盾 | 2 | p1 半开 → 原图（锁死成盾） |
| 13 横扫 | 3 | p1 蓄力 → p2 光刃起 → p3 光弧过中 |
| 15 跃起 | 3 | p1 屈膝 → p2 离地 → p3 衣袂铺满 |
| 16 冰晶阵 | 2 | p1 初破 → 原图（成林炸开） |
| 17 对撞 | 3 | p1 逼近 → p2 接触 → p3 冲击扩张 |
| 21 巨手 | 3 | p1 高悬 → p2 触地 → p3 崩裂 |

**为什么不是每镜都 4 格**：

1. **第 4 格漂移率最高**。镜 10 的 p4 生成出斗笠和金色光环，与角色设定冲突；
   返工时姿势又退回接近 p2 的状态，插值会来回摆。一张 p4 平均要 1.3 次返工。
2. **初态本来就是第 0 格**。像镜 12（伞已张开）、镜 16（冰已炸开）这类"结果态"镜头，
   原图本身就是链的终点，只需要补 1 张"之前"的状态即可，硬凑 4 格反而是注水。
3. **复用已有素材**。镜 13/15/17/21 的 `_b`（上一轮生成的下一个姿势）质量可用，
   直接作为链末格，省下 4 张生成额度。

代价：格数少的镜头（12/16）姿势粒度粗，靠环境位移与形变补足动感。

## 生成原则（每格都必须遵守）

1. **场景锁死**：远景（塔、断柱、石阵、云、雨）位置与形态完全不变。
2. **光线与调色锁死**：同一套青绿主色 + 金色点缀，同一曝光。
3. **只改动作**：肢体朝向、衣袂/发丝拖尾、水花/冰屑/火花的位置与扩散。
4. **链式生成**：`p2` 以 `p1` 为参考图生成，而不是每次都从原图重来。
   这样姿势是"连续演化"的，不会各自为政。
5. **增量递增**：越往后姿势越极端，动势越来越强，形成加速度。

## 文件命名与接线

```
assets/shots/A13_sweep_p1.jpg … _p3.jpg
shots/motion.json:  {"13": {"key_chain": ["A13_sweep_p1","A13_sweep_p2","A13_sweep_p3"],
                            "key_ts": [0.34, 0.52, 0.90]}}
```

`render/lib/shot.py` 会预计算相邻两格的双向光流，播放时按进度落在对应区段，
段内用 ease-out（快起慢收，符合动作片的节奏）。

### key_ts：让关键帧可以"不均匀"分布

`key_ts` 指定每一格在镜头内的时间位置（0..1），默认均匀分布。
这一项解决了一个真实的剪辑问题：动作不能从第一帧就开始。
例如镜 17（对撞，1.6s）：

- `key_ts = [0.45, 0.62, 0.86]`
- 0.0–0.45 两股力量**逼近**（慢，蓄势）
- 0.45–0.62 **接触**（0.27s，快）
- 0.62–0.86 **扩张**（冲击后段）
- 0.86–1.0 停在末格，给剪辑点留余量

如果均匀分布，观众会在第一帧就看到接触，冲击感全没了。

## 一致性检查（每镜必做）

生成后逐镜拼图目检三件事：

1. **背景是否漂移**：塔的位置、断柱数量、云形是否还在原地。
2. **服装是否走样**：镜 10 的 p4 就是因为多出斗笠被判废。
3. **姿势是否单调**：相邻格差异太小（帧差 < 8）会让插值"卡住"，
   太大（> 30）则中间帧容易糊。

实测相邻格光流均值 0.45–1.01px、帧差 11.8–26.9，都在可用区间。
