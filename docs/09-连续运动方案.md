# 09 · 从"PPT 感"到连续运动

> 用户反馈："当前生成的视频有点像 ppt，不像是一个连续动作的视频。"
> 这份文档记录：怎么把这句话变成可测量的指标，怎么定位病因，以及最终用了什么技术手段治它。

---

## 一、把"像 PPT"翻译成一个数字

"像 PPT"不是主观感受，它有明确的物理对应物：**画面内部的像素没有相对运动**。

分两步测量（`scripts/motion_probe.py`）：

1. **全局位移**：相邻两帧用相位相关（FFT cross-power spectrum）估计整体平移量。
   相机推、拉、摇产生的是这一项。
2. **主体局部运动**：先按估出来的全局位移把前一帧配准到后一帧，再取残差（差异大于 60 分位的像素的中位数）。
   衣袂翻飞、雾气流动、水花飞溅、能量脉冲产生的都是这一项。

判定逻辑很干净：

| 情况 | 全局位移 | 局部运动 | 观感 |
|---|---|---|---|
| 静帧 + 2.5D 推拉 | 大 | ≈ 0 | PPT 翻页 |
| 真实的动作镜头 | 中 | 大 | 人物在自己动 |

实测结果（12fps 探针、320×180 灰度）：

| 素材 | 全局位移 | 主体局部运动 | 局部/全局 |
|---|---|---|---|
| 参考片 `original-720p.mp4` | 2.24 px | **35.00 px** | 3.21 |
| 修复前 `青冥·伞_40s.mp4` | 2.38 px | **9.00 px** → 且大半来自雨噪点 | 0.55 |
| 修复后（动作镜抽样） | 1.00 px | **21.50 px** | **8.26** |

结论写进评审量表：新增 `subject_motion`（主体局部运动量，相似度比对参考片）与
`motion_purity`（局部/全局比，防止用"整幅平移"伪装成运动）。

---

## 二、病因：不是相机不够晃，是画面里只有一张皮

原渲染管线的每一帧是这么来的：

```
一张关键帧 → 仿射变换(zoom/pan/rot) → 特效层 → 调色 → 出帧
```

仿射变换是**刚体变换**：画面里任意两点之间的距离恒定不变。
所以无论相机推得多快，画面内部不存在任何形变——这正是 PPT 切换动画的做法。

### 试过但放弃的两条路

1. **加大相机运动**（推拉摇移 + 抖动）。测出来全局位移上去了，局部运动依然 ≈ 9px，改善不了观感，反而晕。
2. **双关键帧形态插值**（`flow_morph`：A→B 光流与 B→A 反向流做前后向一致性插值）。
   两张 AI 关键帧画的从来不是同一个场景，人物站位、塔的位置都不同，插值必然出现双重鬼影。
   已验证失败，`flow_morph` 保留在库里但不在主链路使用。

> 顺带修了一个隐蔽 bug：Horn–Schunck 的 `alpha` 是平滑项权重，
> 在图像归一化到 [0,1] 之后它的合理量级是 0.3~1.0，原来设成 20 会让光流恒等于 0，
> 表现为"光流看起来能跑但永远输出 0"。

---

## 三、方案：把运动写进画面内部

新管线在仿射之后、特效之前插入了**运动层合成**（`render/lib/shot.py: _flow / _layers`）：

```
关键帧 → 仿射(相机) ─┐
                     ├→ 合成速度场 → 单次双线性反向采样 → 特效 → 调色
     分层视差 ───────┤
     局部有机形变 ───┘
```

### 1. 分层视差（parallax）

画面按纵向切成三条带（天空 / 中景 / 地面），每条带跟随相机位移的倍率不同：
0.55 / 1.00 / 1.45。相机横移 10px 时，天空动 5.5px、地面动 14.5px，
层与层之间就产生了**相对位移**——刚体变换做不出这件事。

### 2. 局部有机形变（organic flow）

用低频分形噪声对时间做相位平移，得到一张"布在呼吸 / 雾在流动"的速度场，
再乘一块带羽化的矩形遮罩，**只让该动的区域动**：

- `soft_band(y0,y1,x0,x1,feather)`：羽化遮罩，边缘用 smoothstep，避免出现剪切缝
- `organic_flow(noise, amp, scale, t, drift)`：噪声梯度 × amp + 恒定漂移 drift×t

每镜 2 个运动层，语义对应画面内容：伞面旋转、衣袂后拖、水被劈开、绿焰上窜、
冰晶外扩、云海涌流、尘烬上浮……见 `shots/motion.json`（由 `scripts/author_motion.py` 生成）。

### 3. 单次重采样

视差与形变**先叠加成一个速度场**，再只做一次双线性反向采样。
如果每层单独 warp 一次再混合，等于对同一张图重复插值 3 次，锐度会塌掉。

### 4. 快门运动模糊（shutter）

`Shot.frame(i)` 不再只算一帧，而是算 `shutter` 个子帧取平均：

```python
acc = sum(self._base_at(i + (k + 0.5) / sh - 0.5) for k in range(sh)) / sh
```

因为 `_base_at` 接受浮点时间，"相机 + 形变"都在亚帧尺度上连续，累积出来的就是
**真实的运动模糊**（方向与运动一致），而不是后期加的高斯糊。
动作镜（冲刺、横扫、对撞、白闪、巨手砸落）用 4 个子帧，文戏 1~2 个。

## 四、代价与取舍

| 项 | 修复前 | 修复后 |
|---|---|---|
| 单帧耗时 | 0.50 s | 1.73 s（快门 3~4 子帧） |
| 全片渲染 | 12 min | ~35 min（2 核，无 GPU） |
| 依赖 | numpy / PIL / imageio-ffmpeg | 不变（光流与形变全部用 numpy 手写） |

取舍说明：

- 没有引入 OpenCV / PyTorch。环境里没有 GPU，且 `cv2.calcOpticalFlowFarneback` 在这类
  单帧素材上没有可用信息源——真正需要的是**合成的**速度场，不是估计出来的光流。
- 局部运动是"程序化表演"，本质仍是单张关键帧的形变。它能解决"画面内部零运动"，
  但不等于逐格动画。若要再进一步，需要同一动作的多张连拍关键帧（成本是几何级数）。
