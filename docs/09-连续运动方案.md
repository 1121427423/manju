# 09 · 从"PPT 感"到连续运动：诊断、方案与天花板

> 用户反馈："当前生成的视频有点像 ppt，不像是一个连续动作的视频。"
> 这份文档记录：怎么把这句话变成可测量的指标，怎么定位病因，做了哪几层修复，
> 以及 —— 诚实地 —— 单帧方案的天花板在哪里。

---

## 一、把"像 PPT"翻译成数字

"像 PPT"不是玄学，它对应一个很具体的物理事实：**画面内部的像素之间没有相对运动**。

`scripts/motion_probe.py` 用两步测：

1. **全局位移**：相邻两帧做相位相关（FFT 互功率谱峰值），估计整体平移量。
   相机推、拉、摇产生的都是这一项。
2. **主体局部运动**：按估出的全局位移把前一帧配准过去，求残差（差异高于 60 分位像素的中位数）。
   衣袂翻飞、雾流动、水花、能量脉冲产生的都是这一项。

| 情况 | 全局位移 | 局部运动 | 观感 |
|---|---|---|---|
| 静帧 + 2.5D 推拉 | 大 | ≈ 0 | PPT 翻页 |
| 真实动作镜头 | 中 | 大 | 人物在自己动 |

### 一个必须避开的陷阱：颗粒会冒充运动

第一版探针在参考片上读出 35.00、在本片读出 9.00，看着像个漂亮的量化结论。
但**胶片颗粒和压缩噪声也会产生帧间残差**。把两帧先做 3px 高斯低通再测（"去颗粒"），
数字才有意义：

| 素材 | 局部运动（含颗粒） | **结构性**局部运动（去颗粒） |
|---|---|---|
| 参考片 `original-720p.mp4` | 35.00 | **25.88** |
| 修复前 | 9.00 | **5.11** |
| 修复后（终版） | 11.00 | **5.18** |

去颗粒后差距是 5 倍。**结论很硬：原来的片子几乎没有画面内部运动。**

---

## 二、病因：不是相机不够晃，是画面里只有一张皮

原管线每帧的生成方式：

```
一张关键帧 → 仿射变换(zoom/pan/rot) → 特效层 → 调色 → 出帧
```

仿射是**刚体变换**：画面里任意两点的距离恒定不变。
所以相机推得再猛，画面内部也不存在任何形变 —— 这正是 PPT 转场动画的原理。

### 走过并放弃的三条路（都验证过，写在库里备用）

1. **加大相机运动**。全局位移上去了，局部运动还是 ≈9px，观感只是更晕。
2. **大振幅噪声形变**。把形变幅度提到 90px，整幅画面"煮"成流动的油画，
   人物轮廓随之瓦解 —— 画面质量直接归零。
3. **任意两帧做形态插值**。两张不同镜头的美术图画的从来不是同一个场景，
   插值必然出双重鬼影（`flow_morph` 保留，但只用于第 4 节那种"同场景续帧"）。

> 顺带修了一个隐蔽 bug：Horn–Schunck 的 `alpha` 是平滑项权重，图像归一化到 [0,1] 后
> 合理量级是 0.3~1.0，原来设成 20 会让光流恒等于 0 —— 表现为"代码能跑但永远输出 0"。

---

## 三、方案：把运动分三层写进画面

新管线在仿射**之后**、特效**之前**插入运动合成（`render/lib/shot.py: _flow / _layers`）：

```
关键帧 → 相机仿射 ─┐
                   ├→ 合成速度场 → 单次双线性反向采样 → 特效 → 调色
   分层空间位移 ───┤
   局部有机形变 ───┘
```

### 第 1 层：分层空间位移（真正被看见的那部分）

画面按纵向切成互不重叠的三段，各自以不同速度滑移，羽化 0.11 过渡：

| 层 | 区间 | 速度 | 放进来的内容 |
|---|---|---|---|
| SKY | 0.00–0.36 | 60–110 px/s | 云、雨、光柱、飞石 |
| MID | 0.36–0.82 | 10–60 px/s | **人物整体**（几乎不动） |
| GND | 0.82–1.00 | 90–180 px/s | 水、碎石、霜雾 |

关键取舍：**主体必须保持刚性**。人是观众辨认画面的锚点，一旦被剪切，画面立刻"化掉"。
所以位移全给环境，人物所在的中段只做几像素的呼吸。第一版没做这个隔离，
人物腿部被地面层剪成两截，肉眼可见地散架 —— 这是经过图像检查才发现的。

### 第 2 层：局部有机形变（负责"活着"）

低频噪声对时间做相位平移，得到"布在呼吸 / 雾在流动"的速度场，
乘羽化遮罩后只作用于指定区域（`soft_band` + `organic_flow`）。
幅度只有 4–6px —— 它不承担"运动量"，只负责让边缘永远不死。

另有一层 `kind="bright"`：按亮度把白袍、发丝、光边单独挑出来，
给它们相对身体 16–110 px/s 的自有位移，人就"飘"起来了。

### 第 3 层：双关键帧形态插值（唯一能改变主体姿势的手段）

前两层无论怎么调，主体都是被钉住的。真正的解法只有一个：**让主体换姿势**。
用图像编辑为同一镜头生成"下一个姿势"——场景、光线、构图、配色全部保持不变，
只改动作 —— 然后两帧之间做前向/后向一致性形态插值（`flow_morph`）：
A→B 与 B→A 两套光流互为校验，遮挡区自动偏向"看得见的那一帧"，中间帧不出鬼影。

已接入 **8 个动作镜**（详见 `10-动作镜四格编排.md`）：

| 镜头 | 链 | 变化 |
|---|---|---|
| 10 冲刺 | p1→p2→p3 | 蓄力下沉 → 蹬地爆发 → 光尾前送 |
| 11 相撞 | p1→p2→p3→p4 | 将触 → 接触白热 → 火花放射 → 余波下沉 |
| 12 成盾 | p1→p2→原图 | 半开 → 三分之二 → 锁死成盾 |
| 13 横扫 | p1→p2→p3 | 蓄力 → 光刃起 → 光弧过中 |
| 15 跃起 | p1→p2→p3→p4 | 屈膝 → 离地 → 衣袂铺满 → 腾空最高点 |
| 16 冰晶 | p1→p2→原图 | 初破 → 冰锥成环 → 成林炸开 |
| 17 对撞 | p1→p2→p3 | 逼近 → 接触 → 冲击扩张 |
| 21 巨手 | p1→p2→p3 | 高悬下压 → 触地 → 崩裂 |

姿势链的两项关键控制：

- **`key_ts`**：每格在镜头内的时间位置。动作不能从第一帧就开始 ——
  镜 17 的 `[0.45, 0.62, 0.86]` 让前 0.7 秒都在"逼近蓄势"，接触只有 0.27 秒。
- **`radial` 运动场**：伞面张开、冰锥炸开这类"从中心向外"的动作，
  光流插值做不出来（关键帧只有首末两格），但它是真实存在的运动。
  用 `rad × 高斯衰减 × 羽化带` 生成放射速度场，速度随时间 ease-in。

### 试错记录：大半径径向场会毁画面

镜 12、15 的局部运动偏低（11），我试过把径向场的 sigma 放大到 1.15（画幅尺度）
来模拟"受光物翻转"，结果盾面被吸成一个点、人物被拉成漩涡 —— 直接作废。
教训：径向场只能用于**本身就有放射结构**的画面（伞骨、冰锥），
且 sigma 必须小于主体尺寸；画面尺度的"整体缩放"仍然是刚体变换，
对局部运动指标无效，只会破坏画面。

### 第 4 层：快门运动模糊

`Shot.frame(i)` 不再是"算一帧"，而是算 `shutter` 个亚帧取平均：

```python
acc = sum(self._base_at(i + (k + 0.5) / sh - 0.5) for k in range(sh)) / sh
```

`_base_at` 接受浮点时间，相机与形变在亚帧尺度上连续，累积出的就是**方向与运动一致的
真实运动模糊**，不是后期糊上去的高斯。动作镜用 4 个子帧。

顺带把手持从 0.55px/0.05° 提到 1.6px/0.10°（三频叠加），静镜也有"被拍"的感觉。

## 四、结果，以及为什么数字只涨了一点

| 指标 | 参考片 | 修复前 | 修复后 |
|---|---|---|---|
| 局部运动（12fps 探针，含颗粒） | 35.00 | 9.00 | 11.00 |
| **结构性局部运动（去颗粒）** | **25.88** | **5.11** | **5.33** |
| 8 个动作镜中位 | 47 | 15 | **16.0**（单镜最高 23.5） |

### 一个反直觉的读数：补帧后指标反而降了

给镜 12、15、16 补了中间格之后，逐镜局部运动**没有上升**（12 仍 11，15 仍 11）。
原因在指标定义本身：局部运动测的是**相邻两帧的残差**。同样的总变化，
分摊到更多帧上，单帧残差必然变小 —— 这是除法的必然，不代表动作变差。
观感上补帧后明显更顺（盾面逐帧张开、衣袂逐帧铺开），但数字看不出来。
所以「补帧」与「提指标」是两件事：前者买的是**连续感**，后者要靠**单帧内的位移幅度**。
| 评审子项 `subject_motion`（10fps） | 31.67 | — | 11.00 → 17.9 分 |
| 评审总分 | — | 92.9（历史版本，量表收紧前，且未含该项） | **89.7 / A** |

> 当前成片（第六轮）为 **91.8 / S**，见 `docs/07-评审报告.md`；本节记录的是第三轮补帧期间的读数。

**为什么提升有限，这是必须说清楚的部分。**

参考片的 25.88 意味着每 0.1 秒画面内容移动约 8% 画幅宽 —— 换算到 1080p 是每秒
400 像素以上。那是**逐格动画**的量级：人物每一格都在换姿势。而我们的素材是
**每镜一张静帧**，任何基于这张静帧的技术（位移、形变、光流）都只能让它"形变"，
不能让它"换姿势"。用户看到的"PPT 感"，本质是**关键帧密度**问题，不是运镜问题。

本轮的进展是真实的：画面不再是"一张图缓慢放大"，环境在滑、衣袂在飘、雾在流、
三镜的人物真的换了姿势、动作镜有真实运动模糊。但要跨到参考片的运动量，
只有一条路 —— **提高关键帧密度**。

### 下一步（如果要真正追平参考片）

按动作镜生成 2–4 张连续姿势的续帧（现有 3 张已验证可行），做多段形态插值；
23 镜里 8 个动作镜需要约 16–24 张续帧。管线已经通（`key_b` / `_morph_at`），
成本主要在图像生成与一致性返工。这属于"重做动作设计"，不是调参。

## 五、代价

| 项 | 修复前 | 修复后 |
|---|---|---|
| 单帧耗时 | 0.50 s | 1.6–2.1 s（4 子帧 + 形变 + 形态插值） |
| 全片渲染 | 12 min | 32 min（2 核，无 GPU） |
| 依赖 | numpy / PIL / imageio-ffmpeg | 不变（光流与形变全部 numpy 手写） |

没有引入 OpenCV / PyTorch：环境无 GPU，而且这里需要的不是"估计出来的光流"，
而是"合成的速度场"。
